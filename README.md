# Argonauts — 함께 달리는 크루 위치 공유

> **이름의 유래**: 아르고나우타이(Argonauts) — 아르고호를 타고 함께 원정을 떠난 영웅들. 여러 대의 차가 **한 크루로 같은 목적지를 향해 함께 이동**한다는 의미.

| 항목 | 내용 |
| --- | --- |
| 한 줄 소개 | 친구·가족·동호회가 **크루**를 만들면 **지도 위에 크루 전원의 위치가 실시간으로** 보이고, 목적지·경유지·도착 예정 시간이 공유되며, 크루원 누구나 **목적지 변경을 요청**할 수 있고, 확정된 목적지·휴게소는 **한 번 탭으로 내 내비 경로에 넣는** 그룹 이동 앱 |
| 대상 | B2C — 여러 대로 함께 떠나는 여행·캠핑·골프, 차량 동호회 정모, 친구와 약속 장소에서 만나는 운전자 |
| 원조 모델 | 친구 위치 공유 앱(젠리 류), 카카오맵 위치 공유, 무전기로 하던 차량 행렬 이동 |
| 사용 맥락 | 출발 전 크루 구성(정차) + 주행 중 상태 확인(숫자 위주, 최소 조작) + 휴게소·도착(정차) |
| 카테고리 | **Mobility Services** — 가이드의 "현재 위치 기반 즉각 정보, 경유지 설정"에 해당. (Social/Communication은 주행 중 허용 카테고리 예시에 없어 선택하지 않음) |
| 상태 | 기획 + 구현 가능성 검증 완료 (2026-11-02, 7-1장). 공모전 제출용 |

## 0. 개발 제약 (2026-11-01 Playground 확인)

| 사용 가능 ✅ | 사용 불가 ❌ |
| --- | --- |
| NaviHelper (현재 위치, 목적지·경유지 조회, 경로 상태, 도착 이벤트, **경로 설정·경유지 추가**) | Vehicle Control |
| Vehicle State 조회 (주행 상태·기어 → 정차 판정, UI 제한) | TTS / STT / FusedLocation / LLM SDK |
| 외부 서버 (크루 상태 중계, 친구용 휴대폰 웹) | 빌트인캠 등 OEM 전용 속성 (`signature\|privileged`) |

→ **제어 권한 불필요.** NaviHelper 조회 + 사용자 탭에 의한 경로 요청만 사용.

## 1. 문제 정의 (Pain Points)

| 대상 | Pain Point | 현재 대응 |
| --- | --- | --- |
| 여러 대로 함께 이동하는 운전자 | "어디쯤이야?" 확인하려고 주행 중 전화·메신저 | 동승자가 대신 연락, 운전 중 폰 조작 |
| 행렬 이동 | 앞차가 휴게소에 들어가도 뒤차는 모르고 지나침 → 다시 모이기 어려움 | 미리 정한 휴게소, 무전기 |
| 목적지 맞추기 | 리더가 보낸 주소를 차 내비에 다시 입력 | 카톡 주소 복붙 → 폰 내비 or 수동 입력 |
| 약속 장소에서 만나기 | 서로 몇 분 남았는지 몰라 기다림·재촉 | "출발했어?" 반복 연락 |

휴대폰 위치 공유 앱은 **지도 위 점**만 보여준다. 차에서는 그 정보를 **바로 내 경로로 바꿀 수 있다**는 것이 핵심 차별점.

## 2. 핵심 기능

### F1. 크루 만들기 · 참여 (정차)
- 리더가 차에서 크루 생성 → 6자리 코드 + QR 표시.
- 참여: 다른 Pleos 차량은 앱에서 코드 입력, **Pleos 차량이 없는 친구는 휴대폰 웹 링크**로 참여(위치는 폰 브라우저 위치 사용).
- 크루는 **임시**: 목적지 도착 또는 리더 종료 시 자동 해산, 위치 공유 즉시 중단.

### F2. 실시간 크루 지도 ★핵심
- **지도 위에 크루 전원의 위치를 실시간 표시** (차량 크루원 + 휴대폰 웹 크루원 모두). 크루 목적지·경유지 핀도 함께 표시.
- 차에서 수집해 서버로 전송: 현재 위치(`onCurrentLocationInfo`), 목적지(`onDestinationInfo`), 경유지(`onWayPointInfo`), 경로 상태·남은 거리/시간(`onRouteStateInfo`, `onTripInfo`). 서버 → 크루원에게 WebSocket으로 즉시 전달.
- 각 마커: 이니셜 + 색상, 마커 옆 `3.2km 뒤 · 14:20 도착` 한 줄.
- 지도 하단 크루 리스트(거리·도착 예정 시간·상태 `주행 중`/`휴게소 정차 중`/`도착`).
- **주행 중 / 정차 중 지도 모드 분리** (주행 규제 대응):

  | | 주행 중 (간결 모드) | 정차 중 (전체 모드) |
  | --- | --- | --- |
  | 크루 마커 실시간 표시 | ✅ (위치 갱신 시 즉시 이동, **이동 애니메이션 없음**) | ✅ |
  | 화면 범위 | 크루 전원이 들어오게 자동 맞춤(고정) | 자유롭게 이동·확대 |
  | 조작 | 크루원 마커 탭 → 정보 한 줄만 | 경로 미리보기, 크루원 상세 |
  | 그 외 | 지도 스타일 단순화(라벨 최소), 팝업·채팅 없음 | 목적지 변경 요청, 크루 관리 |

### F3. 목적지 공유 · 변경 요청 ★차량특화
- **크루 목적지는 하나**. 크루 생성 시 리더의 내비 목적지가 크루 목적지가 됨.
- **변경 요청**: 크루원 누구나 새 목적지를 제안할 수 있음.
  - 차에서(정차 중): 내 즐겨찾기·최근 목적지(`getBookmarkInfo`, `getRecentDestinationInfo`) 중 선택, 또는 **지도에서 위치 길게 눌러** 선택.
  - 휴대폰 웹에서: 장소 검색 후 "목적지 변경 요청".
  - 주행 중에는 요청을 만들 수 없음(입력 조작 금지) → 동승자가 휴대폰 웹으로 요청.
- **승인**: 리더 차량에 카드 **"민수님이 목적지를 ○○맛집으로 바꾸자고 해요 [수락] [거절]"** — 주행 중에도 단일 탭으로 응답 가능. 일정 시간 무응답 시 자동 만료.
- **확정 후 따라가기**: 수락되면 리더 내비는 바로 새 경로(`requestRoute()`), 나머지 크루원 차에 **"크루 목적지가 ○○맛집으로 바뀌었어요 [안내 시작]"** → 탭 한 번으로 경로 변경. 지도의 목적지 핀도 즉시 갱신.
- 리더가 크루 앱 밖에서 직접 내비 목적지를 바꾼 경우(`onDestinationChanged`)에도 같은 "따라가기" 카드 전송.
- 동의 없는 자동 경로 변경은 하지 않음(가이드: 사용자 명시적 선택 시에만 경로 전환).

### F4. 경유지 같이 들르기 ★차량특화
- 크루원 누구든 휴게소·주유소·충전소를 경유지로 추가하면(`onWaypointChanged` 감지) 다른 크루원에게 카드: **"지영님이 ○○휴게소에 들러요. [같이 들르기]"**.
- 탭 → `addWaypoint()` (Pleos 경유지 최대 2개 제약 → 꽉 차 있으면 안내만).
- 휴게소 도착(`onWayPointArrived`) 시 "민수 도착 · 지영 5분 후 도착" 표시.

### F5. 만나기 모드
- 크루원의 **현재 위치** 또는 **휴대폰 웹에서 고른 약속 장소**를 목적지로 보내기 → 차에 "안내 시작" 카드.
- 친구가 폰 웹에서 장소 검색 → "차로 보내기" → 차 화면 카드(Send-to-car).
- 서로의 도착 예정 시간 자동 공유 → "출발했어?" 연락 불필요.

### F6. 자동 체크인 · 해산
- 목적지 도착(`onDestinationArrived`) + 정차 → 크루에 "도착" 자동 표시.
- 전원 도착 시 크루 자동 해산 + 위치 기록 삭제(이동 요약만 선택 저장).

### F7. 원정 기록 카드 (선택)
- 크루 이동 요약(총 거리, 들른 휴게소, 도착 순서) 카드 → QR → 폰에서 저장·공유.

## 3. 사용 시나리오 (데모 스토리)

1. 토요일 08:00, 리더 차량에서 크루 "가평 캠핑" 생성 → QR. 친구 A는 Pleos 차량 앱, 친구 B는 폰 웹으로 참여.
2. 리더가 내비 목적지 "○○캠핑장" 설정 → A 차량에 "크루 목적지로 안내할까요?" → 탭 → 경로 시작.
3. 주행 중 A 화면: 지도 위에 리더·A·B 마커가 실시간으로 움직임, 리더 마커 옆 `2.1km 앞 · 09:42 도착`.
4. 리더가 가평휴게소를 경유지로 추가 → A 차량에 "리더가 가평휴게소에 들러요 [같이 들르기]" → 탭 → 경유지 추가.
5. 휴게소 정차 중, B가 폰 웹에서 "캠핑장 가기 전에 ○○막국수" 목적지 변경 요청 → 리더 화면 [수락] → A 차량에 "크루 목적지가 바뀌었어요 [안내 시작]" → 탭.
6. 막국수집 도착 → 자동 체크인 → 전원 도착 → 크루 해산, 원정 카드 생성.

## 6. 사업 모델 & 지표

- **과금**: 기본 무료(크루 4대) → 프리미엄(대규모 크루·동호회 정모, 원정 기록 보관).
- **B2B**: 렌터카 단체 대여(제주 가족 여행 여러 대), 기업 워크숍·투어 차량 이동, 차량 동호회.
- **제휴**: 휴게소·캠핑장·충전소 — **정차 화면에서만** 추천 노출(주행 중 광고는 즉시 반려 사유).
- **지표**: 크루 생성 수/주, 크루당 참여 차량 수, 목적지 따라가기·경유지 같이 들르기 전환율, 웹 참여자의 앱 전환.

## 7-1. 구현 가능성 검증 결과 (2026-11-02, 에뮬레이터 `Pleos_Connect_Argonauts`)

검증 앱(`ProbeService` 포그라운드 서비스 + 3초 조회, NaviHelper 3.0.5)으로 확인.

| 항목 | 결과 | 비고 |
| --- | --- | --- |
| 백그라운드 수신 | ✅ | 내비 화면이 앞에 있고 우리 앱 화면이 `paused`여도 포그라운드 서비스에서 위치·목적지·경유지 조회와 이벤트를 계속 받음 |
| `requestRoute()` | ✅ | 경로 시작 + 내비 화면이 자동으로 앞으로 옴. `onRouteStarted`(소요 시간·거리·통행료) 수신 |
| `addWaypoint()` | ✅ | `onWaypointChanged(FIRST, ADD)` → 경로 재계산. 재계산 중 `onRouteCancelled`가 한 번 오므로 "경로 취소"로 오인하지 않게 처리 필요 |
| 남은 거리·시간(도착 예정) | ✅ | `DestinationInfo.remainDistance/remainTime`(예: 99000m/5760초), 경유지별 `WaypointInfo.remainDistance/remainTime`, `onDrivingInfo`에도 목적지·경유지별 값 |
| `requestTrip()` | ✅ | **경로를 바꾸지 않고** 임의 지점까지 거리·소요 시간·교통 상황 조회(예: 26135m/1628초) → 만나기 모드의 "친구까지 몇 분" 계산에 사용 |
| 즐겨찾기·최근 목적지 | ✅ | `BOOKMARKS`: 집/회사(이름은 빈 값, 카테고리로 구분), `RECENT`: 목적지 목록 → 목적지 변경 요청 후보 |
| 주행 중 화면 | ✅ | `distractionOptimized` 선언 시 D·60km/h에서도 화면 유지 (Hephaestus는 미선언 → 차단 화면) |
| `onDestinationChanged` | ⚠️ | `requestRoute()`로 바꿀 때는 오지 않음 → `onRouteStarted` + 목적지 조회로 변경 감지 |
| 위치 이동 | ❌ (에뮬레이터 한계) | 현재 위치가 판교(37.41272, 127.09468)에 고정. Virtual Console 속도·`emu geo fix`·내비 설정 모두 이동 수단 없음 → **데모는 앱 데모 모드로 위치 이동을 시뮬레이션**, 실차에서 갱신 주기 확인 필요 |

### 판정
- 핵심 기능(실시간 공유, 목적지 따라가기, 경유지 같이 들르기, 목적지 변경 요청, 만나기)은 **현재 SDK로 구현 가능**.
- 주행 중 실시간 지도는 DO 선언으로 표시 가능. 심사 대응은 간결 모드 설계로.
- 크루원 이동은 데모에서 서버/앱의 시뮬레이션 데이터로 보여준다.
